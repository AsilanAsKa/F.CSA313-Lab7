## Зорилго

Уншлагын жагсаалт веб аппликейшнийг exploratory testing аргаар шалгаж, хэрэглэгчийн интерфейс болон API-ийн алдааг илрүүлэх.

## Тестийн хүрээ

- Ном нэмэх, хайх, устгах үйлдэл
- Номын тоолуур болон жилийн утга
- Хэрэглэгчид харагдах мессеж
- Хуудасны холбоосууд
- API хүсэлт, хариу болон алдаатай JSON өгөгдөл

## Илрүүлсэн алдаанууд

1. **BUG-01:** Буруу JSON хүсэлтэд API `400 Bad Request` биш `200 OK` буцаадаг.
2. **BUG-02:** Хуучин хувилбарын холбоос `500 Internal Server Error` буцаадаг.
3. **BUG-03:** Номын жагсаалт 3 номтой байхад API-ийн статистик `total: 4` гэж буцаадаг.

Алдааны дэлгэрэнгүй тайлан `bugs/` хавтсанд, API нотолгоонууд `evidence/` хавтсанд байрлана.

## Дүгнэлт

1. Exploratory testing нь урьдчилан төлөвлөсөн шалгалтаас гадна аппын бодит үйлдлийг судалж алдаа олоход тусалсан.
2. API-ийн алдаатай JSON хүсэлт илгээсэн Saboteur аялал үр дүнтэй байв.
3. BUG-01 нь алдаатай хүсэлтэд буруу HTTP статус буцааснаар илэрсэн.
4. BUG-02 нь хуудасны холбоосыг шалгах үед илэрсэн.
5. BUG-03 нь номын жагсаалт болон статистикийн хариуг харьцуулах үед илэрсэн.
6. API-ийн алдааг `curl -i` командаар шалгаж, бүрэн хариуг нотолгоо болгон хадгалсан.
7. Автомат тестээр API статус болон тоолуурын зөрүүг шалгаж болно.
8. Харин өнгө, харагдах байдал, хэрэглэгчид ойлгомжтой эсэхийг хүн гараар шалгах нь чухал.
9. Цаашид хоосон талбар, давхардсан ном, буруу он, том хэмжээний текст болон том жижиг үсэг ялгадаг хайлтыг шалгах шаардлагатай.

## Хэсэг E — Exploratory testing-ийн дүгнэлт

### E.1. Тестийн аялал ба илрүүлсэн согог

| Тестийн аялал | Илрүүлсэн согог |
|---|---|
| Нүүр хуудас нээж, номын жагсаалт болон тоолуурыг харьцуулах | BUG-03: Жагсаалтад 3 ном байхад нийт номын тоо 4 гэж харагдсан. |
| Хуучин хувилбарын холбоосыг дарах | BUG-02: Internal Server Error гарсан. |
| API-д буруу форматтай JSON илгээх | BUG-01: HTTP 400 хүлээгдсэн боловч HTTP 200 буцсан. |
| Ном хайх, бүх номыг харуулах | Хайлтын үр дүн болон жагсаалтын харагдах байдлыг шалгасан. |

### E.2. Шалгагдаагүй зүйлс

- Олон хэрэглэгч зэрэг ажиллах үеийн зан төлөв.
- Удаан хугацааны ачаалал болон гүйцэтгэл.
- Гар утас, өөр хөтөч дээрх харагдах байдал.
- XSS зэрэг аюулгүй байдлын дэлгэрэнгүй шалгалт.
- Номын талбаруудын бүх төрлийн буруу болон хязгаарын утгуудыг бүрэн шалгах.

Эдгээрийг энэ лабораторийн хүрээнд бүрэн шалгаагүй.

### E.3. Playwright ба хүний нүдээр шалгахын ялгаа

Playwright нь урьдчилан бичсэн алхмуудыг давтан ажиллуулж, тодорхой нөхцөл болон хүлээгдсэн үр дүнг автоматаар шалгахад тохиромжтой. Харин exploratory testing хийх хүн интерфейсийг чөлөөтэй судалж, гэнэтийн зан төлөв, ойлгомжгүй мессеж, харагдах байдлын зөрүү болон өөр өөр үйлдлийн хоорондын асуудлыг илрүүлж чадна.

Энэ лабораторид хүний шалгалтаар номын жагсаалт ба тоолуурын зөрүү, хуучин хувилбарын холбоосын алдааг ажигласан. Автомат API шалгалтаар HTTP хариу болон статистикийн зөрүүг давхар шалгасан.
